# 01. UX/UI ベストプラクティス調査

「マップがあって、ピンタップで概要、さらに詳細へ別タブで飛べる」UI の **業界標準パターン** を整理し、PCWE2026 への適用方針を出す。

---

## 1. 参照したサービス・パターン

### 1-A. プラチナマップ系（イベント・観光向け国産マップ SaaS）

[ストロリー](https://stroly.com/) や [プラチナマップ](https://platinumaps.jp/) などの国産マップサービスが採る典型的な UI:

- **トップ画面**: 全体マップ + フローティング検索バー + カテゴリチップ
- **タップ**: ピン → 半画面ボトムシート（写真 + 名前 + 一行紹介 + 「詳細を見る」ボタン）
- **ボトムシート上スワイプ** で詳細パネル展開
- **「詳細を見る」**: 別タブで個別ページへ遷移
- **絞り込み**: 地図上にピンが多すぎる時のクラスタリング、フィルタトグル

🟢 **本プロジェクトに採用したい点**:
- ボトムシート 2 段階（半画面プレビュー → 全画面詳細 or 別タブ）
- カテゴリチップでフィルタ
- ピンクラスタリング（テント単位での集約）

### 1-B. Google Maps / Apple Maps（汎用マップ UX 標準）

- **タップ → ボトムシート**: 名前・サムネ・⭐︎評価・ジャンルチップ・距離・「経路」「電話」「シェア」「保存」
- **シート上スワイプ**: 写真ギャラリー → 説明 → レビュー → 営業時間
- **シート下スワイプ**: マップ全体に戻る
- **検索バー固定**: 上部または下部

🟢 **採用したい点**:
- ボトムシートのスワイプ操作（縦方向ジェスチャ）
- 「シェア」「保存（お気に入り）」アクション
- 検索バーは常に最前面

🟡 **採用しない点**: GPS 経路（屋内かつ規模が小さいので不要）

### 1-C. SXSW GO / Coachella App（大型フェス向け）

[SXSW GO](https://sxsw.com/mobile/) は 7,000 セッション × 300 会場という超大規模を捌くアプリ。学べることは:

- **「Discover」タブ**: 個人化された推薦（あなたが興味ありそうな出展）
- **ジャンル別ローンチページ**: Conference / Film & TV / Music を独立タブに
- **個人スケジュール**: 「行きたい」リストを保存 → タイムテーブル形式で表示
- **マップ + リスト 2 表示モード**

🟢 **採用したい点**:
- 「行きたい」（ピン保存）機能。LocalStorage で良い
- ジャンル別ローンチ画面（PCWE 版なら「番組ファン向け」「食探し」「体験探し」「無料配布だけ」）
- マップ ⇄ リスト 1 タップ切替

🟡 **採用しない点**:
- ログイン必須機能、SNS 連携、有料機能

### 1-D. SXSW 2025 MAP by Stroly（同人系イベント向け）

[sxsw.stroly.com](https://sxsw.stroly.com/) は SXSW のサードパーティマップで、**手描き調マップ + 公式座標** をハイブリッド。

🟢 **採用したい点**:
- 公式の **正規座標は維持** しつつ **アートワークとしてのレイアウト** を尊重
- 公式マップの「ベクター複製」がライセンス的にグレーなら、座標だけ取って独自デザインで描画

### 1-E. Comic Frontier Interactive Booth Map（同人・即売会向け）

[Medium 記事](https://medium.com/@izrafatch/comic-frontier-interactive-booth-map-things-that-i-learned-7ad578a28cd1) より、コミック即売会のマップ UX で重要な学び:

> 「ナビゲートしながら検索できる」 — 地図のパン・ズームだけで探させない
> 「情報を地図の中に出す」 — 別カタログを開かせない

🟢 **採用したい点**:
- 検索結果がマップ上にハイライト表示される（リストではなく地図の上で答えが出る）
- ピン押下後の情報パネルが「マップを覆い隠さない」（半画面ボトムシート）

### 1-F. Comiket Web Catalog（最大級の同人即売会）

参考: 「Comiket Web Catalog」「サークル.ms」のような、サークル番号 × 配置位置 × ジャンルで検索できる Web カタログ。

🟢 **採用したい点**:
- ブース番号（14-A）を直接入力して即ジャンプ
- 番組（サークル）名の一文字検索 → サジェスト

## 2. 本プロジェクトでの UX 方針

### 2-1. 階層構造（3 レイヤー）

```
[全体マップ] ← フィルタ・検索の結果が反映される
   ↓ タップ
[ボトムシート プレビュー]（半画面 60% 高さ）
   - 番組サムネ・番組名・キャッチ・グッズタグ
   - 「番組詳細を見る」ボタン
   ↓ ボタン押下
[番組詳細ページ]（既存 /booth/[id] へ遷移、別タブ）
```

**3 レイヤー構造の理由**:
- マップ → ボトムシート: ユーザーは「ここ何のブース？」を **マップから離れずに** 把握できる
- ボトムシート → 詳細ページ: 深い情報（物販詳細、X 投稿埋め込み等）は **マップから明確に離脱して** 読む

### 2-2. 押下粒度: テント vs A/B/C/D ブース（要件 #3）

公式マップは **テント単位（14）に A/B/C/D の 4 ブースが格納される** 構造。

#### 結論案: **アダプティブ + 視覚的ヒント**

| ズーム段階 | 押下粒度 | 表示 |
|---|---|---|
| **遠景**（全体表示）| **テント単位** | テント番号のみ。ブース個別ピンは出さない（情報密度抑制） |
| **中景**（5-8 テント表示）| **A/B/C/D 単位** に切替 | テント数字 + A/B/C/D ラベルが小さく出る。各ブースに個別ピン |
| **近景**（1-2 テント表示）| **A/B/C/D 単位**、各ブースに番組サムネ | サムネ + 番組名の一部 |

**理由**:
- 全体マップでテント単位で表示 → 視認性が高く、初見ユーザーが圧倒されない
- ズームすると自然に粒度が細かくなる（Google Maps 式）
- ただし「テント 14 全体」をタップすると **「14-A は番組X、14-B は番組Y...」** とブース 4 つが横並びで出るボトムシートも提供（高速ナビ用）

#### 操作ヒット領域

物理ボタン（指タップ）の最小推奨サイズは **44×44 px**（Apple HIG）。

- テント単位ピン: 60×60 px → 余裕あり
- A/B/C/D 単位ピン: 32×32 px だがテント内 4 区画なので **テント全体を 96×96 px、4 分割で 48×48 px** にすれば達成可能
- ピン同士の最小間隔 8 px

### 2-3. 検索 UX

要件: 「目的の番組が明確にあるとき」と「ない / ふわっとしたとき」両対応

```
┌──────────────────────────────┐
│ 🔍 番組名・ブース番号・グッズで検索 │  ← 上部固定
└──────────────────────────────┘
   ↓ 入力するとサジェスト
   ┌─────────────────────┐
   │ 番組: 愛の抵抗 (11-B)│
   │ 番組: 愛猫日和 (08-C) │
   │ ブース: 14-A      │
   │ グッズ: 占い系 5件   │
   └─────────────────────┘
```

- **番組名サジェスト**: 部分一致 + よみがな（半角/全角あいまい）
- **ブース番号入力**: `14-A` `14a` `014A` 等の正規化
- **グッズキーワード**: 「占い」「コーヒー」「タロット」等のワード → 該当番組を地図でハイライト

検索結果がマップ上に **波紋アニメーション** で点滅 → ユーザーは目を離さずヒット位置を把握。

### 2-4. フィルタチップ（要件 #4）

ボトムバー or 上部固定のチップ群:

```
[全部] [食べ物] [体験・占い] [無料配布] [新作・限定] [両日出展] [土曜のみ] [日曜のみ]
```

- **トグル可能**（複数選択 OR 結合）
- 選択状態は URL に保存 (`?filter=food,experience`)
- 該当しないピンは **半透明 30%** で表示（完全に非表示にすると場所が分からなくなる）

詳細なグッズ分類は [03-merchandise-taxonomy.md](./03-merchandise-taxonomy.md) で定義。

### 2-5. マップ ⇄ リスト切替（要件 #5）

```
┌─────────────────────┐
│ [🗺 マップ] [☰ リスト] │  ← トップに常設
└─────────────────────┘
```

- 同じフィルタ・検索条件を **両ビューで共有**
- リストビュー: グッズタグ + サムネ + 番組名 + ブース位置（クリックでマップに戻ってその場所にズーム）
- 切替時に **どこを見ていたかのコンテキスト保持**（リストでクリックしたピンがマップで開いた状態になる）

### 2-6. ボトムシート設計

```
┌─────────────────────┐
│  ┃ ← drag handle    │  半画面 (60vh)
│ [サムネ]             │
│ 愛の抵抗 (pcwe-002)  │
│ #ZINE #ペーパー     │
│ ブース: 11-B (両日)  │
│ ─────────────       │
│ ★ お品書き           │
│ Love Letter / ZINE  │
│ あすけん生活...      │
│                     │
│ [📖 番組詳細を見る →]│  ← 別タブで /booth/pcwe-002 へ
└─────────────────────┘
```

- スワイプダウンで閉じる
- スワイプアップで全画面化（最大 90vh）
- 「番組詳細を見る」が CTA、別タブで開く（マップを失わない）

### 2-7. アクセシビリティ（最初から）

[W3C SVG-AAM 1.0](https://www.w3.org/TR/svg-aam-1.0/) と [TPGi](https://www.tpgi.com/using-aria-enhance-svg-accessibility/) のベストプラクティスに従う:

- `<svg role="application">` または `role="img"` + `<title>` `<desc>`
- 各ピンに `<a>` 要素 + `aria-label="ブース 14-A 愛の抵抗"`
- `tabindex="0"` で Tab フォーカス可能
- Enter/Space でボトムシート起動
- Esc でボトムシート閉じる
- スクリーンリーダー用に **マップと同等のリストビュー** が常にアクセス可能（リストモードはアクセシビリティ的にも重要）

### 2-8. パフォーマンス

- **SSG**: マップ HTML はビルド時に固定生成、JS は最小
- **コード分割**: マップ周辺の重いライブラリ（あれば）は dynamic import
- **画像**: 番組サムネは既存 `/thumbnails/XXX.jpeg` を使い回し、ボトムシートで読み込み
- **オフライン**: PWA / Service Worker で会場利用時の電波弱を救う（v2.5）

## 3. 採用しないパターンと理由

| パターン | 不採用理由 |
|---|---|
| Google Maps の埋め込み | 実会場（HOME/WORK VILLAGE）の屋内配置を表現できない |
| Mapbox / Leaflet | 地理情報ベースのライブラリは過剰（オーバーキル）。SVG 直書きで足りる |
| ヒートマップ | 当日 LIVE 訪問データが取れない以上、嘘の混雑表示はできない |
| AR ナビ | 屋内 GPS が不安定。要件・効果に対して工数が見合わない |
| ログイン機能 | 当日 5 秒で使えることが最重要。サインアップで離脱が痛い |

## 4. ライブラリ選定

第一候補（軽量・SSG 親和性高）:

- **生 SVG + Tailwind**: シンプルなテント矩形なら自前で十分。React コンポーネント化
- **react-zoom-pan-pinch**: タッチ・マウスのパン・ピンチズームを最小コードで
- **`@radix-ui/react-dialog`**: ボトムシート（既に Tailwind 4 ベースに馴染む）
- **`@react-spring/web`** or **Framer Motion**: スワイプジェスチャ・スプリング

第二候補（重め）:

- **react-svg-pan-zoom**: 機能リッチだが API が古め
- **Konva**: Canvas 系。SSG・SEO・スクリーンリーダーで弱い

→ 詳細は [05-implementation-plan.md](./05-implementation-plan.md) で確定。
