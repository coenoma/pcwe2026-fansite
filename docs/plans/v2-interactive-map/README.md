# v2: インタラクティブ会場マップ

PCWE2026 ファンサイトの第2の柱。**142 番組ある中から「自分が会いたい番組」「知らないけど面白そうなブース」を会場で迷わず見つける** ための会場マップ機能を設計・実装する。

> 本ディレクトリは **設計フェーズ** のドキュメント群。実装着手前に、ここで論点を出し切る。実装中に判断が変わったらこのドキュメントを更新してから動く。

---

## なぜマップが必要か

### 現状の課題

- 番組詳細ページ `/booth/[id]` は揃ってきた（v1: 物販詳細 99/142 done、画像活用ハイブリッド済み）
- でも **「自分は今ブース 14-A の前に立っている。ここは何の番組？　次にどこに行けばいい？」** という当日のリアルな動きには応えられない
- 公式の JPEG マップ（`day1.jpg` / `day2.jpg`）はあるが、ただの画像。**タップで番組情報が出ない／土日切り替えがない／検索できない**

### このマップが提供する体験

| 場面 | 解決策 |
|---|---|
| 「目的の番組のブースに行きたい」 | 番組名検索 → ピンが点滅してハイライト |
| 「14-A ってどこの番組だっけ？」 | テント → A/B/C/D タップ → ボトムシート概要 |
| 「番組知らないけど食べ物系で面白いとこ探したい」 | グッズ分類フィルタ（食・体験・占い…） |
| 「土曜行ったけど日曜にもう一回来る、別番組見たい」 | 土日切り替えで違う番組が出る同じ位置を見比べ |
| 「マップは閉じてリストでざっと見たい」 | マップ⇄リスト ワンタップ切替 |

## 重要な事実（実装前に頭に入れること）

### 142 番組と 31 テントのギャップ

`data/programs.json` を分析した結果:

| 指標 | 値 |
|---|---|
| 全番組 | 142 |
| `boothNumber` ユニーク数 | 142（1〜144、重複なし）= **論理ブース ID** |
| 物理テント数（公式マップ画像） | 31（テント 1〜31） |
| 物理ブース数最大 | 31 × A/B/C/D = **124 ポジション** |
| 両日 (sat,sun) 出展 | 33 件 |
| sat のみ | 55 件 |
| sun のみ | 54 件 |
| エリア | 全て `free`（有料エリアなし） |

**142 > 124 のため、論理ブース ID = 物理ポジションの 1:1 対応は不可能**。

つまり:
- 公式 `boothNumber`（pcwe-XXX の XXX、001〜144）は **論理 ID** であり、物理位置とは別概念
- マップ上の「14-A の土曜」と「14-A の日曜」は **異なる番組** になり得る
- **物理位置 ↔ 論理ブース ID のマッピング表が別途必要** （現データには未登録）

### このマッピングはどこから取る？

PCWE 公式が日別フロアマップ JPEG（[Day1](https://podcastexpo.jp/) / Day2）を公開している。これを目視 + OCR で起こす作業が必要。詳細は [02-data-and-svg.md](./02-data-and-svg.md) 参照。

## 要件（ユーザー指示の整理）

| # | 要件 | 詳細 |
|---|---|---|
| 1 | 2 日間対応 | 土曜（5/9）と日曜（5/10）で別マップ。同 14-A でも土日で別番組 |
| 2 | SVG 化 | 公式 JPEG をそのまま貼るのではなく、同じレイアウトで SVG を自作。タップ可能領域・アクセシビリティ・ダーク対応のため |
| 3 | 押下粒度 | 14-A 単位（ブース）と 14 単位（テント）どちらが適切か。ズーム別アダプティブも視野 |
| 4 | グッズ分類フィルタ | 番組ファン向け以外の切り口（食・体験・珍しいもの・無料配布等）を強化 |
| 5 | マップ⇄リスト切替 | フィルタ結果を双方で確認できる |
| 6 | JSON 再整備 | 4 のフィルタに耐えるグッズタクソノミーを 142 番組分整える |

### 私（Claude）からの追加提案（要件には書かれていないが、当日体験を豊かにする）

| # | 追加要件 | 理由 |
|---|---|---|
| α | **動線提案 / 「お気に入りピン → 推奨ルート」** | 142 ブースを目的なくウロウロは疲れる。気になるピンを n 個立てたら最短巡回ルートを提示 |
| β | **混雑回避タイミング** | 開場直後・閉場前・昼食時間で混むエリアが変わる。当日 LIVE データはないが、過去 PCWE 経験ベースで「11:00-13:00 は中央列が混む」など静的ヒント |
| γ | **無料配布だけ／体験だけ／食だけマップ** | 番組ファン以外にとってのとっつきやすさ最大化。これだけで 1 タブ用意するレベル |
| δ | **ARIA + キーボードナビ** | SVG はデフォルトで非アクセシブル。Tab で次ピンへ、Enter で詳細、Esc で閉じる、を初期実装で入れる |
| ε | **オフライン耐性** | 会場の電波は弱い前提。SSG + Service Worker でマップ JSON / SVG を事前キャッシュ |
| ζ | **「現在地っぽい」表現** | 屋内 GPS は不安定なので実装しない。代わりに「メインゲートから近い」「中央エリア」など静的セクション表現で十分 |
| η | **共有可能 URL** | `/map?day=sat&pin=14-A&filter=food` のようにフィルタ・選択状態を URL に残す。SNS で「ここ気になる」共有しやすく |
| θ | **「いま空いてる」マークの手動運用** | 当日運営者がブースの混雑を 3 段階で更新できる管理画面（v2.5）|
| ι | **リスナーの「会えた！」記録** | 番組ホストに会えたブースに「✅会えた」スタンプを押せる。当日の達成感ゲージ。LocalStorage 保存 |

α〜ζ は v2 初版（5/9 リリース目標）に入れたい。η〜ι は v2.5 として継続検討。

## このプロジェクトのトーン

PCWE2026 ファンサイトは **コエノマの「番組へのリスペクト + リスナーへの愛」** を体現する場所。
マップ機能でも:

- 番組ホストの努力（物販企画・グッズ準備・告知）が一番見やすく出る配置
- リスナーが「初めて知る番組」と「既に推している番組」の両方を発見できる導線
- 公式マップ画像をリスペクトしつつ、当日のリアルな動きをサポートするツール

この精神は実装中もブレないようにする。
