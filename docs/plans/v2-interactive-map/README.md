# v2: インタラクティブ会場マップ

PCWE2026 ファンサイトの第2の柱。**142 番組ある中から「自分が会いたい番組」「知らないけど面白そうなブース」を会場で迷わず見つける** ための会場マップ機能を設計・実装する。

> 本ディレクトリは **設計フェーズ** のドキュメント群。実装着手前に、ここで論点を出し切る。実装中に判断が変わったらこのドキュメントを更新してから動く。

---

## なぜマップが必要か

### 現状の課題

- 番組詳細ページ `/booth/[id]` は揃ってきた（v1: 物販詳細 99/142 done、画像活用ハイブリッド済み）
- でも **「自分は今ブース 14-A の前に立っている。ここは何の番組？　次にどこに行けばいい？」** という当日のリアルな動きには応えられない
- 公式の JPEG マップ（`day1.jpg` / `day2.jpg`）はあるが、ただの画像。**タップで番組情報が出ない／土日切り替えがない／検索できない**

### このマップが提供する体験

| 場面 | 解決策 |
|---|---|
| 「目的の番組のブースに行きたい」 | 番組名検索 → ピンが点滅してハイライト |
| 「14-A ってどこの番組だっけ？」 | テント → A/B/C/D タップ → ボトムシート概要 |
| 「番組知らないけど食べ物系で面白いとこ探したい」 | グッズ分類フィルタ（食・体験・占い…） |
| 「土曜行ったけど日曜にもう一回来る、別番組見たい」 | 土日切り替えで違う番組が出る同じ位置を見比べ |
| 「マップは閉じてリストでざっと見たい」 | マップ⇄リスト ワンタップ切替 |

## 重要な事実（実装前に頭に入れること）

### 142 番組と 32 テントの構造

`data/programs.json` + 取得済みブース位置 md を分析した結果:

| 指標 | 値 |
|---|---|
| 全番組 | 142 |
| `boothNumber` ユニーク数 | 142（1〜144、重複なし）= **論理ブース ID** |
| 物理テント数（公式マップ画像） | **32**（テント 1〜32、32 はキッチンブース） |
| 物理ブース数最大 | テント 1-7・18-19・30-31 が single + 8-17・20-29 が quad（A/B/C/D）|
| 両日 (sat,sun) 出展 | 33 件 |
| sat のみ | 55 件 |
| sun のみ | 54 件 |
| エリア | 全て `free`（有料エリアなし） |
| キッチンブース（テント 32） | 番組出展なし、特別ブース扱い |

**マップ上の「14-A の土曜」と「14-A の日曜」は異なる番組になり得る**（quad テントで両日異なる番組が同じ A 区画に座る）。

### マッピングデータ取得状況

✅ **取得済み**:
- ソース: `data/sources/booth-map/booth-positions-source.md`（PCWE 公式提供）
- 確定 JSON: `data/booth-positions.json`（テント 1-29 の 175 スロット）
- 公式画像: `public/images/map/pcwe2026-day1.webp` / `pcwe2026-day2.webp`（DL 可能化）

⚠️ **未確定**:
- **テント 30, 31**（公式マップ画像には描かれているが、ソース md に割当未記載）
- **3 番組**が programs.json に存在しない: `PodWalker` (24-C 土) / `まかないラジオ` (26-B 日) / `アイデア刺激法 〜どう？〜` (13-B 日)
  - これらは PCWE 公式の追加出展者で、142 番組に含まれていない可能性
  - データ取得経路の再確認 + programs.json への追加可否の判断が必要

→ 確定 175 スロット + 未確定 3-7 スロットで、リリース時点では **テント 1-29 + 32 (キッチン)** まで先行表示し、30, 31 と未マッチ 3 番組は **「準備中」プレースホルダー** で表示する運用方針。

## 要件（ユーザー指示の整理）

| # | 要件 | 詳細 |
|---|---|---|
| 1 | 2 日間対応 | 土曜（5/9）と日曜（5/10）で別マップ。同 14-A でも土日で別番組 |
| 2 | SVG 化 | 公式 JPEG をそのまま貼るのではなく、同じレイアウトで SVG を自作。タップ可能領域・アクセシビリティ・ダーク対応のため |
| 3 | 押下粒度 | 14-A 単位（ブース）と 14 単位（テント）どちらが適切か。ズーム別アダプティブも視野 |
| 4 | グッズ分類フィルタ | 番組ファン向け以外の切り口（食・体験・珍しいもの・無料配布等）を強化 |
| 5 | マップ⇄リスト切替 | フィルタ結果を双方で確認できる |
| 6 | JSON 再整備 | 4 のフィルタに耐えるグッズタクソノミーを 142 番組分整える |

### 私（Claude）からの追加提案 + v2 必須/v2.5 ライン引き

ユーザー指示「最低限（リリースに必須・体験的に使いづらいがない）までを定義していれましょう」に従い、各提案に必須/任意ラインを引きます。

| # | 追加要件 | v2 必須？ | 理由 / リリース判定 |
|---|---|:---:|---|
| α | **動線提案 / お気に入り → 推奨ルート** | 🟡 v2.5 | お気に入りピン保存自体は v2 必須（後述）、推奨ルート計算は v2.5 |
| β | **混雑回避タイミングヒント** | 🟡 v2.5 | 静的ヒントは README ページに別記、マップ内表示は v2.5 |
| γ | **食だけ / 体験だけ / 無料配布だけマップ** | 🔴 v2 必須 | 散策型来場者の主要導線。フィルタチップで実現（要件 #4） |
| δ | **ARIA + キーボードナビ** | 🔴 v2 必須 | アクセシビリティは初期実装で入れる方が後工事より安い |
| ε | **オフライン耐性 (PWA / Service Worker)** | 🟡 v2.5 | 会場電波弱は実害だが、Vercel CDN + 軽量データなら初回読み込み後はブラウザキャッシュで実用十分。Service Worker は v2.5 |
| ζ | **「現在地っぽい」手動指定** | 🟢 v3 | 必須ではない、楽しい機能。実装重め |
| η | **URL 状態保存（フィルタ・選択を URL に）** | 🔴 v2 必須 | SNS シェア、ブラウザ戻る、ブックマーク全部に効く。実装軽い |
| θ | **「いま混んでる」手動更新** | 🟢 v3 | 当日運営の手間が大きい、効果も読めない |
| ι | **「会えた」記録（LocalStorage）** | 🔴 v2 必須 | 当日体験のキー機能。LocalStorage で軽い |

加えて要件には書かれていない、新たに必須と判断した v2 機能:

| # | 機能 | v2 必須？ | 理由 |
|---|---|:---:|---|
| κ | **お気に入りピン保存（LocalStorage）** | 🔴 v2 必須 | 「行きたい」リスト保存、UX のキー |
| λ | **公式画像 DL ボタン** | 🔴 v2 必須 | 当日電波弱でもオフライン参照できるよう公式 webp の DL リンクをマップ画面に常設（ユーザー要件追加） |
| μ | **ファンガイドトップと同じテイスト** | 🔴 v2 必須 | primary 色（#dc725a 系オレンジ）+ secondary（青）+ accent-cyan の既存ブランドカラーを踏襲（ユーザー要件追加） |

## このプロジェクトのトーン

PCWE2026 ファンサイトは **コエノマの「番組へのリスペクト + リスナーへの愛」** を体現する場所。
マップ機能でも:

- 番組ホストの努力（物販企画・グッズ準備・告知）が一番見やすく出る配置
- リスナーが「初めて知る番組」と「既に推している番組」の両方を発見できる導線
- 公式マップ画像をリスペクトしつつ、当日のリアルな動きをサポートするツール

この精神は実装中もブレないようにする。
