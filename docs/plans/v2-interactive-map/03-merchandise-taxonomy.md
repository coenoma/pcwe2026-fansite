## 1. 設計の出発点

### 1-1. ユーザーの 2 つの来場目的

| 目的タイプ | ユーザー像 | 必要な情報 |
|---|---|---|
| **明確な目的型** | 「○○ラジオの T シャツ買いたい」「△△を聴いてる、ホストに会いたい」 | 番組名検索、ピン直接ジャンプ |
| **散策型 / 偶然の出会い型** | 「番組はあまり知らない、面白そうな所を回りたい」「家族 / 友人を連れて来た」 | カテゴリで絞り込み、知らない番組との接点 |

**現状の課題**: 散策型ユーザーへの導線が弱い。物販詳細ページは番組ファン向けの粒度。

### 1-2. ユーザーが言ったとっかかり（重要発言）

> 「食べ物系だったら番組知らなくてもとっつきやすいよね、とか。その場での体験系もそうかもね、知らなくても楽しめる可能性あり。その体験系には含まれるかもだけど、めちゃ珍しいやつ・・・占いとか？前は肌測定とかあったね」

> 「ただのアクスタとかマグカップとかTシャツとか、いわゆるの番組グッズは番組ファン向けだからね、そういうので絞れる必要は意外とないのかも？と思ったり」

→ **散策型に響く切り口は限定された数カテゴリで十分**。番組ファン向けの細かい分類（アクスタ、マグカップ、ステッカー…）は **絞り込みフィルタには出さない** 方がノイズが少ない。

## 2. グッズタクソノミー（2 層構造）

### 2-1. レイヤー 1: 散策型向け 6 カテゴリ（絞り込みフィルタの主役）

```
[🍴 食・飲み物]  [🎟 体験・参加型]  [🔮 珍しい・話題系]
[🎁 無料配布]   [✨ 新作・限定]    [📕 ZINE・読み物]
```

| ID | ラベル | 何が入るか | 想定来場者 |
|---|---|---|---|
| `food-drink` | 🍴 食・飲み物 | コーヒー豆、ハーブ茶、ジェラート、調味料、お菓子、酒 | 散策型・全員（試食・小腹空き） |
| `experience` | 🎟 体験・参加型 | 占い、タロット、似顔絵、チェキ、ガチャガチャ、ワークショップ、対戦ゲーム | 散策型・カップル・友人連れ |
| `rare-curious` | 🔮 珍しい・話題系 | 肌測定、AI 診断、即興演奏、特殊技術系（実装は要マニュアル選別） | 散策型・話題作りしたい層 |
| `free-distribution` | 🎁 無料配布 | 番組フリーペーパー、ノベルティしおり、サンプル、配布物 | 全員（コスパ良い）・初訪問者 |
| `limited-new` | ✨ 新作・限定 | NEW GOODS、初販、PCWE 限定、先着販売 | ファン + 限定好き散策型 |
| `zine-book` | 📕 ZINE・読み物 | ZINE、書籍、雑誌、漫画、フリーペーパー | 文芸好き・コミケ的来場者 |

**設計判断**:
- 6 個に絞った（多すぎると散策型が疲れる）
- 各カテゴリ「何があるか想像できる」アイコン必須
- **複数カテゴリの所属 OK**: 「無料の番組フリーペーパー」は `free-distribution` + `zine-book` 両方タグ付け
- フィルタチップは OR 結合（押すたびに追加され、ヒット数が増える）

### 2-2. レイヤー 2: 番組ファン向け詳細種別（絞り込みフィルタには出さない）

番組詳細ページや「物販一覧」のリストモードで参考表示するためのメタ情報。フィルタ UI には出さない。

| ID | ラベル | 何が入るか |
|---|---|---|
| `apparel` | 👕 アパレル | T シャツ、キャップ、エコバッグ、トート、タオル、ポーチ |
| `paper-stationery` | 🖊 紙物・文具 | ステッカー、しおり、ポストカード、ペン、メモ、カレンダー |
| `goods-acrylic` | 🔑 アクリル・バッジ | アクリルキーホルダー、缶バッジ、ラバスト、ピンバッジ、チャーム |
| `goods-tableware` | ☕ タンブラー類 | マグカップ、タンブラー、コースター、グラス |
| `audio-music` | 🎵 音源・映像 | CD、ミュージックカード、限定音源 USB、デモ音源、DVD |
| `goods-misc` | 🧴 その他物販 | 入浴剤、香り系、雑貨、生活アイテム |

**理由**: 散策型はこれらを見たくない、ファンは番組ページに辿り着くので個別ページで詳細を見ればよい。

### 2-3. その他のメタ的軸（横串フィルタ）

カテゴリ軸とは独立してかかるフィルタ:

| ID | ラベル | 値 |
|---|---|---|
| `day` | 出展日 | `sat` / `sun` / `both` |
| `area-section` | エリア | テント番号レンジ（例: 1-7 / 8-11 / 12-31）+ メインゲート近 / 奥 |
| `genre` | 番組ジャンル | カルチャー、文芸、食、映画…（既存 17 ジャンル） |

## 3. データ表現（programs.json への追加）

### 3-1. `merchandiseTags` 番組レベル集約

```json
{
  "id": "pcwe-022",
  "name": "ねむれぬ夜にはラブレター",
  "official": {
    "merchandise": [...],
    "merchandiseDetails": [...],
    "merchandiseTags": ["food-drink", "free-distribution", "limited-new", "zine-book"]
  }
}
```

**設計**:
- 配列。複数所属 OK
- レイヤー 1（6 カテゴリ）のみ採用。レイヤー 2 は別フィールド `merchandiseSubTypes` で持つか、不要なら省略
- スキーマ：`z.array(z.enum(['food-drink', 'experience', ...]))`

### 3-2. `merchandiseSpotlight` 散策型向け一行コピー

カテゴリだけでは何があるか伝わらないので、**散策型向けに「これ目当てでも来る価値あり」を一行で書く** フィールドを追加。コエノマ運営が手書きで書く。

```json
{
  "merchandiseSpotlight": "本茶セットの試飲ができる。1 日のスタートにぴったり"
}
```

UI 上の使い所:
- マップ上のボトムシートで番組名の下に小さく表示
- カテゴリフィルタヒット時のリストカードに表示
- **142 件全部に書く必要なし**。書ける番組（食・体験・珍しい系で目を引くもの）にだけ書く

### 3-3. スキーマ定義

```ts
// src/lib/types.ts に追加
export const MerchandiseTagSchema = z.enum([
  'food-drink',
  'experience',
  'rare-curious',
  'free-distribution',
  'limited-new',
  'zine-book',
]);
export type MerchandiseTag = z.infer<typeof MerchandiseTagSchema>;

export const MerchandiseSubTypeSchema = z.enum([
  'apparel',
  'paper-stationery',
  'goods-acrylic',
  'goods-tableware',
  'audio-music',
  'goods-misc',
]);

// OfficialInfoSchema に追加
{
  ...,
  merchandiseTags: z.array(MerchandiseTagSchema).optional(),
  merchandiseSubTypes: z.array(MerchandiseSubTypeSchema).optional(),
  merchandiseSpotlight: z.string().min(8).max(60).optional(),
}
```

## 5. UI: フィルタ表現

### 5-1. フィルタチップ（マップ画面トップ）

```
┌─────────────────────────────────┐
│ 🔍 検索                         │
├─────────────────────────────────┤
│ [全部] [🍴食] [🎟体験] [🔮珍しい] │
│ [🎁無料配布] [✨新作] [📕読み物]  │
│ ─────────                       │
│ [両日] [土] [日]                 │
└─────────────────────────────────┘
```

- 「全部」を選ぶと全フィルタ解除
- カテゴリチップは複数選択可（OR 結合）
- 日付チップは排他選択（`day=both` がデフォルト）
- 選択状態は URL 同期: `/map?cat=food-drink,experience&day=sat`

### 5-2. ヒット数表示

選択直後:

```
"🍴食・🎟体験 で絞り込み: 12 件"
```

- ヒットしたピンが地図上で **不透明 100%**、外れたピンは **30% 半透明**
- リストモードでは該当 12 件のみ表示

### 5-3. ヒット 0 件のとき

```
"該当ブースは見つかりませんでした。
 [全部] フィルタを外す　or  [☰] リストで見る"
```

ガッカリさせない言葉選びにする。

### 5-4. デフォルト推奨フィルタ

URL に何も指定がないときは **「全部」** がデフォルト。ただし当日 5/9・5/10 にアクセスすると **その日に出展する番組のみ** が初期表示される（自動 `day=sat` or `day=sun`）。日付フィルタの初期値だけは賢く動的に。

## 7. 検索インデックス設計

要件 #4「目的の番組が明確 / そうでない」両対応のため、検索エンジン的な工夫:

### 7-1. インデックス対象フィールド

| フィールド | 重み | 例 |
|---|---|---|
| 番組名 | 5.0 | 「愛の抵抗」 |
| ホスト名（あれば） | 3.0 | 「あさちゃん」「内海あさ」 |

### 7-2. 部分一致 + よみがな対応

- **正規化**: 半角全角・カタカナひらがな統一、英数字 lowercase
- **よみがな**: 番組名のよみがな辞書を `data/program-yomi.json` に持つ（手動か、kuromoji.js で自動）
- **エイリアス**: 「らじお」→「ラジオ」「ラジヲ」、「占い」→「タロット, 鑑定」もカバー

### 7-3. 高速化

142 件 × 平均 5 物販 = ~700 アイテム。クライアントサイド全件突合で十分軽い。
ライブラリは [Fuse.js](https://www.fusejs.io/)（fuzzy 検索）か自前。

## 9. 補足: なぜ「番組ファン向け詳細」をフィルタに出さないか

> ユーザー発言: 「ただのアクスタとかマグカップとかTシャツとか、いわゆるの番組グッズは番組ファン向けだからね、そういうので絞れる必要は意外とないのかも？」

これは正しい。理由:

1. **番組ファンはまず番組名で検索する**。物販種別から逆引きしない
2. **「Tシャツのある番組」を絞り込んでも、結果はほぼ全番組** → フィルタとして機能しない
3. **散策型はそもそも個別物販に興味なし**。「面白いブース」を探している
4. UI の認知負荷を上げない

ただし **`limited-new`（新作・限定）はファン向けでも欲しい**。「PCWE 限定 / 当日販売 / 先着」という時間軸の希少性は **行動を促す**。これだけは例外的にレイヤー 1 に入れた。
