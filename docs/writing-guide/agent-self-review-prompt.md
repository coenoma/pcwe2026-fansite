# エージェント・セルフレビュー依頼文（60 → 100 点化フェーズ）

各エージェントが自分の担当 wip を、ガイドと既存お手本 10 番組と照らし合わせて
100 点に引き上げるための **完全共通テンプレ**。

**前提**: 同一セッションでの継続依頼。前回のキックオフで `$MY_ID` 環境変数を
設定済みのため、エージェントごとの書き換え・冒頭の「あなたは agent-XX」表記も不要。

## 使い方（コエノマ向け）

各エージェントセッションに **📋 ここから貼り付け** 〜 **📋 ここまで貼り付け**
の本文を **そのまま** 貼るだけ（エージェントごとの書き換え不要）。

## ミッション（60 → 100 点化）

あなたが既に書いた wip JSON は「合格ライン（60 点）」。
今回はそれを **100 点（番組制作者本人や常連リスナーがニヤッとする品質）** に
引き上げる磨きの工程。

「合格ライン」と「100 点」の差は、初稿を客観視して、ガイドと既存お手本 10 番組と
**並べて見劣りしないか** を厳しく問い直すところにある。

## 必読ドキュメント（前回読んだから飛ばす、は禁止）

`docs/writing-guide/fan-guide-writing-guide.md`

  温度差 / もじり / 自他往復 / 招待）
- **§4.1.5** catchphraseLines の **6 つのコツ** + NG 反例
- **§6 NG パターン**（特に「他番組フレーズの流用」「公式 description のコピペ」）
- **§7 落とし穴チェックリスト**（経験則 12 個）
- **§9 自己レビューチェックリスト**（提出前必読、全項目）
- **§10.1** 既存 10 番組の good 例（型ごとに整理）
- **§10.2** vibe × themeFont マッピング表

## 自走ループ（自分の担当 wip 全部のレビューが終わるまで）

### Step 1: 自分の担当 wip 一覧を確認
```bash
npm run fan-guide-status -- --agent $MY_ID
```
🟡 のリストから **未レビュー** の 1 件を選ぶ（先頭から順に進めれば重複しない）。
ID は `pcwe-XXX` 形式（例: `pcwe-020`）。

### Step 2: 現行 wip と公式情報を再読
```bash
# 自分が書いた現行 wip
cat data/sources/fan-guide-wip/pcwe-XXX.json

# 公式情報（リサーチ素材）
cat data/sources/official/pcwe-XXX.json
```
公式ブースページ（`https://podcastexpo.jp/booth/pcwe-XXX/`）と Spotify など
リンク先も **改めて** 開く。前回のリサーチで見落としがないか確認。

### Step 3: 60 → 100 点に上げる観点で批判的チェック

自分の現行 wip を「**他人が書いた文章**」として批判的に読み、以下の各項目で
「No」が出る箇所を **すべて洗い出す**。「No」が改善ポイント。

#### catchphrase 周辺
- [ ] §4.1 の **9 つの型** のどれに当てはまる？型が曖昧なら、当てはめ直すと刺さるか
- [ ] 番組固有の **動詞 / 名詞** が catchphrase に含まれている？
- [ ] **価値転換** が起きている？（事実の羅列ではなく、読み手にとっての価値に飛んでいる）
- [ ] **他番組の good 例フレーズ** を一切流用していない？
  - 例: 「静けさを語る」「お守りに変える」「世界に雑に同意しない」「人間らしく生きる哲学」
    「ふと見つかる」「LINE で誘われた気分」「Gyoza Jockey」「ニッチ全振り」「尺に収まらなかった」
  - これらは **その番組固有の発見** なので、別番組に使うと番組が没個性化する
- [ ] catchphrase が **公式 description の言い換えだけ** で終わっていない？
- [ ] catchphrase が **番組名の言い換え**（「○○は△△する番組」）になっていない？
- [ ] 「楽しい」「素敵な」「魅力的な」「最高の」「あの大人気の」など一般論ワードが入っていない？

#### catchphraseLines 周辺
- [ ] catchphrase が **30 字超え** で、意味的に二段構えなら `catchphraseLines` を設定した？
- [ ] §4.1.5 の **6 つのコツ** に沿って分割している？
  - 意味の塊で割る / 1 行 10〜20 字目安 / 24 字超え NG / 行末は読点か句点 /
    数字・英数字の塊は分断しない / 行頭が記号や英数字で始まる行は美しい / 振り→答えのタメ
- [ ] `catchphraseLines` を連結したものが catchphrase と意味的に一致している？

#### subCatch
- [ ] **「何の番組か」を端的に**（出自 / 形式 / 配信頻度のいずれか）伝えている？
- [ ] catchphrase の繰り返しになっていない？
- [ ] 公式 description の冒頭丸写しになっていない？

#### targetListener
- [ ] **属性ラベル**（年齢・性別・職業）だけで終わっていない？
- [ ] **心の動き / 状態 / 悩み / 欲求** で書かれている？
- [ ] 「全ての人」「みんな」のような万人向け表現になっていない？
- [ ] 「〜してください」「〜しましょう」のような営業文になっていない？

#### genre / tags / vibe
- [ ] **genre** は番組の一番濃いテーマと一致している？
- [ ] **tags** が **3 軸ミックス**（雰囲気 / シーン / 内容）からバランス良く拾われている？
- [ ] 公認セット外の独自タグを作っていない？
- [ ] **vibe** が公式の文体・ホスト構成と整合している？

#### themeColor / themeFont（任意フィールドだが、推せる材料があれば）
- [ ] **themeColor** がロゴやアートワークの主要色を反映している？（白に近すぎ・黒すぎは NG）
- [ ] **themeFont** が §10.2 マッピング表の方針と整合している？
- [ ] vibe デフォルトでも自然に見える場合は、無理に指定せず省略 OK

#### スタンス全般
- [ ] 「公式」表記をしていない？
- [ ] 営業文（「ぜひ」「〜しましょう」）になっていない？
- [ ] 断定しすぎていない？（「絶対」「間違いなく」を避け、「〜かも」「〜ような」でやわらかく）
- [ ] 番組制作者の意図に反する深読み・脚色をしていない？
- [ ] 公式 description の固い文体が残っていない？「ぼく」キャラに引き戻せている？

### Step 4: 改善後の最終版を wip に上書き

Step 3 で洗い出した No を一つずつ潰してリライト。改善後を
`data/sources/fan-guide-wip/pcwe-XXX.json` に **そのまま上書き保存**（コメント禁止の素 JSON）。

ファイルパスとファイル名を絶対に間違えないこと:
- ✅ 正: `data/sources/fan-guide-wip/pcwe-XXX.json`
- ❌ 誤: `data/sources/fan-guide/pcwe-XXX.json`（こちらに直接書くのは禁止）
- ❌ 誤: `data/sources/fan-guide-wip/pcwe-XXX.wip.json`（拡張子は `.json` のみ）
- ❌ 誤: 他エージェントの担当 ID のファイル名で書く

### Step 5: スキーマ検証
```bash
npm run merge-fan-guide -- pcwe-XXX --dry-run
```
✅ なら検証 OK。❌ ならエラーに従って wip を直し、再度 dry-run。
**統合（merge）は実行しない**（コエノマが最後に手動で行う）。

### Step 6: 改善ログを内部メモに残す（最後の完了報告で使う）

このまま自分のメモとして保持:
```
pcwe-XXX | 採用した型: △△ | 弱点: 〜〜 | 改善のキモ: 〜〜
```

### Step 7: Step 1 に戻り、まだレビューしていない 🟡 wip を選んで繰り返す

担当 wip すべてが「100 点」になるまで続ける。

## 100 点とは（評価基準）

| 観点 | 60 点 | 100 点 |
|---|---|---|
| catchphrase | 公式の要約に近い | 番組制作者本人がニヤッとする独自フレーズ |
| subCatch | 「何の番組か」が伝わる | ファン視点の補足が効いている |
| targetListener | 属性で書けている | 「この人だな」と固有の人物像が浮かぶ |
| 全体 | NG パターンを避けている | 既存お手本 10 番組と並べて見劣りしない |

「60 点」と「100 点」の差は、**最後の磨き 5〜10 分**にある。
**お手本との比較** が一番確実な物差し。

## 絶対に守るルール

- ❌ **他エージェントの担当 ID には触らない**（自分の担当外を編集すると先祖帰りリスク）
- ❌ **`data/sources/fan-guide/` に直接書き込まない**（必ず `data/sources/fan-guide-wip/` 経由）
- ❌ **`assignments.json` / `booth-ids.json` / `data/sources/official/` を編集しない**（読み取り専用）
- ❌ **既存お手本 10 番組のフレーズを流用しない**
- ❌ **LLM API キーを使った自動生成パイプを組まない**
- ❌ **`npm run merge-fan-guide` を `--dry-run` 無しで実行しない**（統合はコエノマの担当）

## 完了報告

担当 wip 全部のブラッシュアップが終わったら、以下を出力して終了:

```
✅ ブラッシュアップ完了: N 件

各番組の改善サマリ:
  pcwe-XXX | 採用した型: △△型 | 弱点: 〜 → 改善のキモ: 〜
  pcwe-YYY | 採用した型: △△型 | 弱点: 〜 → 改善のキモ: 〜
  ...

⚠️ 保留（情報不足等）: K 件（あれば、理由とともに列挙）
```

各行 1 文ずつでよい。これがコエノマの最終レビュー時の手がかりになる。お疲れさまでした。
```
