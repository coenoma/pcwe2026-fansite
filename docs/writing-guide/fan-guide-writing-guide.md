# ファンガイド ライティングガイド（並列 AI 10 人運用想定）

**最終更新**: 2026-04-29（v1.6.1：お手本 10 番組の型・マッピング表・3 フェーズフローを追加）
**対象読者**: PCWE2026 ファンガイドの fan-guide JSON を執筆する LLM エージェント / 人間のレビュアー

---

## 0. このドキュメントの位置づけ

`data/sources/fan-guide/{id}.json` の中身を、144 番組ぶんスケーラブルに書くためのガイド。

- **想定運用**: 並列 AI 10 人が、1 人 1〜数番組を担当して独立に下書きする
- **品質保証**: 並列実行でも品質を揃えるため、「文字数」「軸構造」「NG パターン」「自己チェックリスト」を機械検証可能なレベルまで明文化する
- **AI 利用ポリシー**: AGENTS.md ルール 7（AI API 禁止）を改訂し、**「AI 下書き＋人間校正」を許容**する。詳細は §11

**並列 AI が「これだけ読めば書ける」**ことを目標とする。podmate-cli の `pm guide` 同様、依存ドキュメント参照を最小化している。

### クイックナビゲーション（最初の 10 分で読む）

時間が限られているなら、以下の順で読めば最低限の品質は出せる：

1. **§2 哲学**（このサイトのスタンス）— 30 秒
2. **§4.1 catchphrase の 9 つの型** + **§10.1 各型の good 例**（計 10 番組）— 5 分
3. **§5.0 執筆 3 フェーズ**（事実抽出 → 解釈構築 → ライティング）— 1 分
4. **§9 自己レビューチェックリスト**（提出前必読）— 1 分
5. **§4.4 タグ 3 軸**（公認セット） — 30 秒

その後、自分の担当番組に近い「型」を §10.1 から探して、骨格を真似て書き始める。

## 2. 哲学：このサイトは「非公式ファンガイド」

執筆者は「ぼく（コエノマ）」というファンの立場で書く。**公式の書き直しではなく、刺さる人の心に届ける言い換え**。

- ❌ 「〇〇について語る番組」（説明）
- ❌ 「楽しいトークが聴ける番組」（一般論）
- ❌ 「初心者にもおすすめ」（誰にでも刺さる ＝ 誰にも刺さらない）
- ✅ 「本の感想じゃなくて、本がくれた静けさを語る番組。」（番組固有の動詞 + 価値転換）
- ✅ 「DJ ならぬ Gyoza Jockey が、毎週火曜、焼き餃子を回す。」（番組固有の名乗り + もじり）
- ✅ 「他人のおへそを見つけているうちに、自分のおへそが、ふと見つかる。」（自他往復で読み手の体験に転換）

**ファン視点で、その番組らしさが「言い当てられている」と本人や常連リスナーがニヤッとする** が完成ライン。

「ぼく」キャラの一貫性:
- 一人称は「ぼく」（コエノマのキャラ）。番組への目線は **ファン / 同志** であって、評論家ではない
- 「（半分ジョーク、半分本気）」のような **メタな揺らぎ表現は使わない**（v1.3 で確認済み）
- 「！」は控えめに（タイトル末尾やサブテキストの 1 箇所までが目安）

## 3. fan-guide JSON スキーマ（厳守）

`src/lib/types.ts` の `FanGuideSchema` と完全一致させること。zod でビルド時検証されるため、文字数や enum 違反は即座にエラーになる。

### 出力ファイルの全体形

```jsonc
{
  "id": "pcwe-XXX",          // 必須・ファイル名と一致
  "fanGuide": {
    "catchphrase":         "string (15〜60 字、推奨 30-50 字)",
    "catchphraseLines":    ["string", "string"],  // optional・2〜4 行、§4.1.5 参照
    "subCatch":            "string (10〜50 字、推奨 20-40 字)",
    "genre":               "Genre enum（§4.3）",
    "tags":                ["string", ...],   // 1〜6 個、推奨 3-5 個、§4.4 のセットから
    "targetListener":      "string (20〜120 字、推奨 50-80 字)",
    "vibe":                "Vibe enum（§4.5）",
    "themeColor":          "#RRGGBB （optional、未指定なら vibe デフォルト）",
    "themeFont":           "ThemeFont enum（optional、§4.7、未指定なら vibe デフォルト）"
  }
}
```

### よくある違反

- `id` がファイル名と不一致 → ビルド時に警告（突合不能）
- `catchphrase` が 14 字以下 / 61 字以上
- `tags` が 7 個以上、または §4.4 のセット外の文字列を含む
- `genre` が §4.3 の 17 種以外
- `themeColor` が `#FFF` のような 3 桁形式（必ず 6 桁）

## 4. 各項目の品質基準

### 4.1 catchphrase（30〜50 字推奨）

「**この番組を聴くと、何が手に入るか / なぜ聴くか**」を 1 文で。

**3 原則**（podmate-cli の品質ガイドに倣う）:
1. 公式説明から「**番組固有の動詞 / 名詞**」を 1 つ抜く（「お茶」「装丁」「失敗」など）
2. それを「**読み手にとっての価値**」に転換（「お茶 → 静けさ」「装丁 → 雑に同意しない」「失敗 → お守り」）
3. **比喩・対比・独自フレーズ**で記憶に残す（番組名と同じ語彙を繰り返さない）

**典型的な型**（既存 10 番組から抽出した型集 — 実例は §10）:

| 型 | パターン | 採用例 |
|---|---|---|
| 差別化型 | 「A じゃなくて、B を語る。」 | pcwe-006「本の感想じゃなくて、本がくれた静けさを語る」 |
| 行為型 | 「A が、B する 1 時間。」 | pcwe-040「漫画家と装丁デザイナーが、世界に雑に同意しない 1 時間」 |
| 変換型 | 「A を、B に変える。」 | pcwe-072「誰にも言えない失敗を、お守りに変える」 |
| 補完型 | 「A に収まらなかった B を、ここで。」 | pcwe-118「新聞の "尺" に収まらなかった話を、ここで聴ける」 |
| 二段型 | 「A の解説のあとに、B が始まる。」 | pcwe-097「最新 AI ツールの解説のあとに、『人間らしく生きる』哲学が始まる」 |
| 温度差型 | 「A 派・B 派・C 派の N 人で、X。」 | pcwe-052「スピリチュアル派・歴 20 年派・理論派の 3 人で、競馬の難しさをほどく」 |
| もじり型 | 「A ならぬ B が、C する。」 | pcwe-119「DJ ならぬ Gyoza Jockey が、毎週火曜、焼き餃子を回す」 |
| 自他往復型 | 「他人の A を見ているうちに、自分の A が見つかる。」 | pcwe-127「他人のおへそを見つけているうちに、自分のおへそが、ふと見つかる」 |
| 招待型 | 「A の気分で聴ける B。」 | pcwe-100「中学の同級生 2 人に、LINE で誘われた気分で聴ける宅飲み雑談」 |

**型を選ぶコツ**:
- 公式 description に「**3 人**」「**毎週木曜**」などの**数字や強い属性**があれば → 行為型 / 温度差型
- 番組名や活動が「**他に類例がない造語**」(Gyoza Jockey 等) → もじり型 / 自他往復型
- 番組が「**入口の敷居を下げている**」（初心者向け、難しさをほどく等） → 招待型 / 補完型
- 番組が「**二段構え**」（解説 + 思想、雑談 + コーナー等） → 二段型
- 番組が「**価値観の主張**」を持っている → 差別化型 / 変換型

**避ける**:
- 「楽しい番組」「素敵な番組」「魅力的な番組」「最高の〇〇」「大人気の〇〇」「今話題の〇〇」（一般論・主観バイアス）
- 番組名そのものの言い換え（「俺思は俺が思うことを語る番組」「聴く餃子は餃子を聴く番組」）
- **既存番組のフレーズを使い回す**（「静けさを語る」「お守りに変える」など、ガイドの good 例で使われた語をそのまま流用）
- 60 字超え（モバイルカードでレイアウト崩れ）

### 4.1.5 catchphraseLines（改行指定、optional）

Hero（番組詳細ページ）の catchphrase を **意味の切れ目で確実に改行** したい場合に、行配列で
指定するフィールド。レスポンシブ幅に依らず必ず指定位置で改行される。

```json
"catchphrase": "最新 AI ツールの解説のあとに、「人間らしく生きる」哲学が始まる。",
"catchphraseLines": [
  "最新 AI ツールの解説のあとに、",
  "「人間らしく生きる」哲学が始まる。"
]
```

**ルール**:
- **最低 2 行、最大 4 行**（モバイル可読性のため）
- 各行 **1 字以上**（空行禁止）
- `catchphraseLines` を **連結したものが catchphrase と意味的に一致** すること
  - 句読点の位置・スペース有無は柔軟に揺らして OK（厳密な文字一致は機械チェックしない）
  - ただし「内容を変える」改行は NG（catchphrase と異なる主張を入れない）
- **未指定の場合は catchphrase が 1 行で表示**される（強制ではない）

**改行位置を決める 6 つのコツ**（10 番組の執筆経験から抽出）:

1. **意味の塊で割る** — 主節・従属節の境界、または接続助詞「、〜うちに、」「〜のあとに、」の **直後** で割る。文の意味の流れに沿って読み手が自然に呼吸できる位置を探す。
   - 例: pcwe-127「他人のおへそを見つけているうちに、」「自分のおへそが、ふと見つかる。」

2. **1 行 10〜20 字を目安に、24 字超えは原則 NG** — モバイル幅でも崩れず読める文字数。24 字を超えるとブラウザが勝手に折り返し、意図した改行位置がズレる。
   - 例外: 固有名詞や独自フレーズが連なる **意味の一塊**（pcwe-052「スピリチュアル派・歴 20 年派・理論派の」23 字）は 1 行で見せるために許容

3. **行末は読点 `、` か句点 `。` で閉じる** — 中途半端な位置（助詞や名詞の途中）で割らない。句点で終わる行を最終行にすると締まりが出る。

4. **数字・英数字・記号の塊は分断しない** — 「20 年派」「3 人で」「AM 6:00」「Gyoza Jockey」「LINE」など、半角文字や記号で構成された一塊は 1 行内に収める。
   - pcwe-097: 「最新 AI ツールの解説のあとに、」（"AI" を割らない）
   - pcwe-119: 「DJ ならぬ Gyoza Jockey が、」（英字 2 単語をまとめて）

5. **行頭が記号や英数字で始まる行は視覚的に整う** — `「` `『` で始まる引用句、英字大文字で始まる固有名詞は、改行頭に置くとリズムが生まれる。
   - pcwe-097 の 2 行目「『人間らしく生きる』哲学が始まる。」（鉤括弧始まり）
   - pcwe-119 の 1 行目「DJ ならぬ Gyoza Jockey が、」（大文字英字始まり）
   - pcwe-100 の 2 行目「LINE で誘われた気分で聴ける宅飲み雑談。」

6. **2 行目を「答え」に、1 行目を「振り」にする** — 1 行目で問いかけや状況を提示し、2 行目で回答や転換を見せると、改行が「タメ」として機能する。
   - 例: pcwe-040「漫画家と装丁デザイナーが、」(振り)「世界に雑に同意しない 1 時間。」(答え)
   - 例: pcwe-097「最新 AI ツールの解説のあとに、」(振り)「『人間らしく生きる』哲学が始まる。」(答え)

**反例（NG な改行）**:

| NG | 何が悪い |
|---|---|
| 「漫画家と装丁デザイ」「ナーが、世界に雑に...」 | 単語の途中で割っている |
| 「焼き餃子を回す」「。」 | 句点だけが残る |
| 「、本がくれた静けさを語る番組。」（行頭が読点）| 行頭が句読点 |
| 「DJ なら」「ぬ Gyoza Jockey が、」 | 助詞の途中で割っている |
| 「20」「年派・理論派の」 | 数字を分断している |
| 「最新 AI ツールの解説のあとに、『人間らしく生きる』哲学が」「始まる。」 | 1 行目 32 字超え（24 字オーバー） |

**反映先**:
- ✅ **番組詳細ページ Hero**（BoothHero）— 蛍光ペン下線が各行ごとに引かれる
- ❌ **カード表示**（ProgramCard / Curation / Gacha 結果 / Quiz 結果）— line-clamp 前提で
  catchphrase の 1 行版を使用（縦に伸びすぎないため）

**書く時の判断基準**（指定する／しない）:

| 状況 | 判断 |
|---|---|
| catchphrase が 30 字超えで、意味的に二段構え | **指定推奨** |
| catchphrase が 20 字以下で 1 行が自然 | **省略 OK** |
| catchphrase 中に独自フレーズが含まれていて、改行で強調したい | **指定推奨**（例: pcwe-097 の「『人間らしく生きる』哲学」を 2 行目頭に） |
| catchphrase が 1 文の流れで切れ目を入れると逆に冗長 | **省略 OK** |

迷ったら **指定する** 方を選ぶ（Hero での視認性が確実に上がる）。

実例は §10.1 の各 good 例を参照。10 番組すべてに `catchphraseLines` が設定されており、
6 つのコツのどれを使ったか観察できる。

### 4.2 subCatch（20〜40 字推奨）

「**何の番組か**」を簡潔に。catchphrase が「**なぜ聴くか**」、subCatch が「**何**」。

- 「1 冊の本を、1 杯のお茶とともに。」（道具立てだけ提示）
- 「元ハガキ職人 3 人組の、毎週金曜カルチャートーク。」（出演者属性 + 配信頻度 + 内容）
- 「ゲイと独女の、失敗エピソード共有番組。」（属性 + 形式）

**避ける**:
- catchphrase の繰り返し
- 公式 description の冒頭丸写し

### 4.3 genre（17 種 enum）

`src/lib/types.ts` の `GenreSchema` から 1 つだけ選ぶ。

```
カルチャー / 文芸・読書 / 食 / 映画 / 音楽 / 旅 / 暮らし
恋愛・ジェンダー / ビジネス / AI・テック / 子育て・教育
ニュース・社会 / 歴史 / 科学・学問 / スポーツ / コメディ / その他
```

**判断基準**:
- 一番濃いテーマを選ぶ（複数当てはまっても 1 つに絞る）
- 迷ったら「リスナーが検索する語」で決める（「映画感想 + 雑談」→ `映画`、「ビジネス書解説」→ `ビジネス` ではなく `文芸・読書`）
- 「その他」は最終手段。当てはまるものがどうしても無い番組（瞑想 BGM 等）にだけ使う

### 4.4 tags（3〜5 個推奨、3 軸ミックス）

`src/lib/tag-axis.ts` で **3 軸**に分類されている。各軸からバランス良く 1 個ずつ拾うのが理想。

| 軸 | 値（公認セット） |
|---|---|
| **雰囲気（mood）** | 笑える / じっくり / 軽快 / 内省的 / 熱量高い / 癒し / 知的 / 共感 |
| **シーン（scene）** | 朝向き / 夜向き / 通勤 / 作業 BGM / 寝る前 |
| **内容（content）** | ニッチ / 学べる / 考えさせる / 元気が出る / 寄り添う / マイノリティ / 二人以上の掛け合い / 一人語り |

**ルール**（厳守）:
1. **必ず公認セットの中から選ぶ**。新しいタグの創作禁止（軸分類が壊れる + 既存フィルタが効かなくなる）
2. **3 軸からバランス良く**（4 個なら例: 雰囲気 2 + シーン 1 + 内容 1）
3. **同義語の重複禁止**（「笑える」と「軽快」を両方付けない）
4. **断定しすぎない**（「絶対に朝向き」は無い。シーンタグは「最も合うシーン」を 1 つ）

**新タグを足したい場合**:
- 自分の判断で勝手に追加せず、`docs/writing-guide/fan-guide-writing-guide.md` に課題として記録 → 提出時にレビュアーへ報告
- 採用決定したら `src/lib/tag-axis.ts` と本ガイドを同時更新する

### 4.5 vibe（7 種 enum）

`src/lib/types.ts` の `VibeSchema` から 1 つだけ選ぶ。UI のアクセントライン色 / フォントが連動する。

| Vibe | キーワード | 例 |
|---|---|---|
| `earnest` | 誠実、論考型 | 創作分解、丁寧な対談 |
| `contemplative` | 内省的、静けさ | 読書、瞑想系、ひとり語り型 |
| `energetic` | 熱量、テンポ | お笑い系、深夜ラジオ |
| `conversational` | 共感、二人以上の温度 | 失敗共有、女子トーク |
| `intellectual` | 知的、解像度を上げる | ニュース解説、学問系 |
| `humorous` | 笑い、軽妙 | コメディ、ゆるい雑談 |
| `laid-back` | くつろぎ、生活密着 | 暮らし系、夜のラジオ |

**判断のコツ**:
- 公式 description の語彙が固いか / 軽いか
- ホストが 1 人か / 複数か（複数なら `conversational` か `energetic` 寄り）
- ジャンルとの組み合わせで自然な vibe を選ぶ（例: `ニュース・社会` × `humorous` は意外な組み合わせなので、本当にコメディ寄りでない限り避ける）

### 4.6 targetListener（50〜80 字推奨）

「**こんな人に刺さる**」を、**悩み or 状態**で書く。属性ラベル（年齢・性別）でなく、**心の動き**で書くのがコツ。

- ✅ 「クリエイターとして『自分はそう思わない』を抱えながら作っている人。」
- ✅ 「SNS のスピードに少し疲れている人。」
- ✅ 「ニュースを『読む』だけじゃ足りない人。」
- ❌ 「20 代の女性」「ビジネスマン」（属性ラベルだけ）
- ❌ 「全ての人におすすめ」（誰にも刺さらない）

2 文構成が書きやすい：「[状況・属性] な人。 [心の動き・欲求] な人。」

### 4.7 themeColor / themeFont（optional）

番組らしさを 1 段ブースト。指定しなくても vibe デフォルトが効くので必須ではないが、推せる材料があれば積極的に。

**themeColor**:
- 番組ロゴ / アートワークの主要色を `#RRGGBB` で（PIL や ColorPick で抽出）
- 文字可読性を考え、彩度高すぎ・明度高すぎの色は避ける（カードの白背景で視認性が落ちる）
- 公式が使っている色を流用するのが安全
- Vibe デフォルトとほぼ同じなら省略でよい

**themeFont** (`ThemeFontSchema`):
```
klee-one         手書き温かみ           → contemplative / 暮らし系
noto-serif-jp    知的・落ち着き         → earnest / intellectual / 文芸
rocknroll-one    印象的・太字           → energetic / コメディ
dot-gothic-16    レトロ・遊び心         → humorous / レトロカルチャー
shippori-mincho  上品・和               → laid-back / 和系
zen-kaku         ニュートラル現代       → conversational / どれにも合うデフォルト系
```

ジャンルの濃さに従って選ぶ。迷ったら省略（vibe デフォルトが効く）。

## 5. リサーチ手順（執筆前の必須インプット）

並列 AI が「公式 JSON だけ見て書く」と一般論になりがち。**必ず 1 番組につき 5〜10 分のリサーチを入れる**。

### 5.0 執筆フェーズの分け方（フロー）

雑にいきなり書くと「公式の文体に引きずられた一般論」が出る。以下の **3 フェーズ** を分けて
進めると質が安定する。

```
Phase 1: 事実抽出      ┐
                       ├─ 「公式が何を書いているか」だけを集める（解釈しない）
リサーチ ──────→ メモ ─┘
                       ┌─ 「読み手にとっての価値転換」を考える
Phase 2: 解釈構築 ─────┤   採用する型を §4.1 から選ぶ
                       └─ vibe / themeColor / themeFont を仮置き
                       ┌─ catchphrase / subCatch / targetListener を組み立て
Phase 3: ライティング ─┤
                       └─ §9 セルフレビュー → JSON 保存
```

**Phase 1（事実抽出）でメモすべきこと**:
- 番組固有の **動詞 / 名詞**（「お茶」「装丁」「失敗」「おへそ」「Gyoza」など）
- 番組固有の **属性 / 構成**（ホスト人数、出自、配信頻度、コーナー名）
- 公式が **明示している差別化ポイント**（「専門用語ナシで」「初心者向け」「ゆる〜い」など）

**Phase 2（解釈構築）で問いかけ**:
- この番組固有の動詞 / 名詞は、聴き手にとって何の **価値転換** になる？
  - 例: 「お茶」 → 「静けさ」、「装丁」 → 「世界に雑に同意しない」、「LINE」 → 「誘われた気分」
- §4.1 の型のどれが一番この番組に合う？
- vibe は公式の文体・ホスト構成と整合しているか（堅いか軽いか、1 人か複数か）

**Phase 3（ライティング）の順序**:
1. catchphrase を **型に当てて** 1 行で書く（30〜50 字）
2. subCatch で「**何の番組か**」を端的に（20〜40 字、出自 + 形式 + 配信時間など）
3. tags は **3 軸ミックス** で（雰囲気 / シーン / 内容、§4.4）
4. targetListener は **心の動き** で書く（属性ラベルではない、§4.6）
5. themeColor / themeFont は推せる材料があれば（§4.7）

この順序を守ると、catchphrase で番組の核を捉え、subCatch・tags・targetListener が自然に
それを補強する構造になる。

### 5.1 必読ソース（優先順）

1. **公式ブースページ**: `https://podcastexpo.jp/booth/{id}/`
   - `data/sources/official/{id}.json` に既に抽出済み。`description` と `hosts` を読む
2. **Spotify / Apple Podcasts**（あれば）
   - 番組ページの「番組について」「最新エピソードのタイトル一覧」を見る
   - 直近 5 エピソードのタイトルから「この番組の本当の濃さ」がわかる
3. **X（旧 Twitter）**: 番組公式 / ホストアカウント
   - **読み取り専用**。投稿・返信は絶対にしない（CLAUDE.md 個人ルール）
   - 直近のポストから「番組のトーン」「リスナーの呼ばれ方」を観察
4. **note / website**（あれば）
   - 番組の世界観・運営者の文体を把握

### 5.2 集めるべき素材

- 番組の **固有名詞**（コーナー名、定型句、ホストの口癖）
- 番組の **直近の話題**（最新数本のエピソードタイトル）
- 番組の **対象 / 立ち位置**（誰に向けて、どんな立ち位置で語っているか）
- 番組の **トーン**（軽い／重い／真面目／ふざけ）

### 5.3 書く前の問いかけ（self-prompt）

執筆を始める前に、自分（AI）に問いかけてメモしてから書き始める。

- この番組を 1 文で説明するなら？
- この番組を聴いて「ハマる人」は、どんな悩み・欲求を持っている？
- この番組と似た番組と比べたとき、何が違う？
- この番組のホストが、自分の番組を一言で言うなら何と言いそう？

## 6. 避けるべきパターン（NG 集）

### 6.1 catchphrase の NG

| NG | 理由 |
|---|---|
| 「楽しい / 素敵な / 魅力的な番組」 | 一般論。具体性ゼロ |
| 「〜について語る番組」 | 説明文。価値転換が無い |
| 「初心者にもおすすめ」 | 万人向け表現は誰にも刺さらない |
| 番組名の言い換え | 番組名で既に伝わっていることを繰り返している |
| 「あの大人気の」「今話題の」「最高の」 | 主観バイアス。本サイトのスタンスと不一致 |
| 60 字超え | UI レイアウト崩れ |
| **他番組のフレーズ流用** | 「静けさを語る」「お守りに変える」「世界に雑に同意しない」など、ガイドの good 例にある語をそのまま使うと番組が没個性化する。**型は流用 OK、フレーズは流用 NG** |
| **公式 description のコピペ・要約** | 公式の固い文体がそのまま残り、「ぼく」キャラが死ぬ。必ず Phase 2（§5.0）で価値転換させる |

### 6.2 tags の NG

| NG | 理由 |
|---|---|
| 公認セット外の独自タグ | 軸分類が壊れる、既存フィルタ無効化 |
| 7 個以上 | UI 表示で 3 個までしか出ない（情報過多） |
| 1 個だけ（ジャンル唯一指定）| 多軸検索が機能しない |
| 「面白い」「良い」 | 形容詞タグは情報量ゼロ |

### 6.3 targetListener の NG

| NG | 理由 |
|---|---|
| 属性ラベルだけ（「20 代女性」）| 心の動きが書かれていない |
| 「全ての人」「みんな」 | ターゲット設計の放棄 |
| 営業文（「〜してください」「〜しましょう」）| ファン視点と不一致 |

### 6.4 全体の NG

- **「公式」表記**（AGENTS.md 9 違反）
- **AI 生成感丸出しの定型句**（「素晴らしい番組」「魅力的なコンテンツ」）
- **断定的すぎる表現**（v1.3 で「〜かも？」基調に統一済み。「絶対」「間違いなく」は避ける）
- **本人の意図と乖離した深読み**（思想を勝手に強く読み取らない。事実から離れない）

## 7. 落とし穴チェックリスト（経験則）

### 7.1 公式情報の罠

- ❶ **og:description が物販リスト**
  公式ブースページの og:description が「【出店予定】グッズ A、グッズ B…」のことがある。`fetch-booth-info.ts` で除外しているが、念のため自分の目でも確認

- ❷ **公式の `hosts` 配列が空**
  公式が記載してないだけで、Spotify には書いてあることが多い。Spotify を必ず見る

- ❸ **`name` の末尾「ー1冊の本をお茶とともに」のサブタイトル**
  ロゴ表示では邪魔になる。`shortName` を補うべきか担当者で判断（このガイドの責務外、別タスクで処理）

### 7.2 タグ／vibe の罠

- ❹ **ジャンル × vibe の意外な組み合わせは慎重に**
  「ニュース・社会」× `humorous` は刺さるリスナーが極端に絞られる。本当にユーモア優位なら OK だが、迷ったら `intellectual` か `conversational`

- ❺ **「マイノリティ」タグの安易な付与**
  本人がマイノリティ視点を主軸に置いている番組にだけ付ける。表面的な属性で判断しない（「女性ホスト＝マイノリティ」ではない）

- ❻ **「ニッチ」タグはほどほどに**
  全番組ニッチに見えるが、PCWE 出展の中で相対的にニッチな番組（再生数少ない／趣味性が極端）にだけ付ける

### 7.3 themeColor の罠

- ❼ **白に近い色は禁止**（`#FFFFFF` `#FAFAFA` 等）
  カード背景が白なので border が消える

- ❽ **真っ黒（`#000000`）も避ける**
  hex 透明度オーバーレイが効かなくなる。最低 `#1A1A1A` 程度の濃いグレーに留める

### 7.4 ライティング全般の罠

- ❾ **公式 description の文体に引きずられる**
  公式は固い書き方が多い。ファンガイドの「ぼく」キャラに引き戻すこと

- ❿ **冒頭の AI 定型句**（「この番組は…」「〇〇な番組です」）
  catchphrase の主語を「この番組」で始めない。番組固有の名詞や動詞で始める

- ⓫ **既存 good 例のフレーズを流用する**
  「静けさを語る」「お守りに変える」「世界に雑に同意しない」などはそれぞれの番組固有の
  発見であって、別番組に使うと番組が没個性化する。**型は流用 OK、フレーズは流用 NG**

- ⓬ **JSON にコメントを残してしまう**
  ガイド §10.1 は jsonc で例示しているが、提出物は厳格な JSON。`//` や `/* */` を
  そのままコピペすると `npm run build:programs` で zod エラー以前に JSON.parse が失敗する

## 8. 並列 AI 運用の作法

### 8.1 1 番組 = 1 ファイル独立

- 各並列 AI は他の番組の fan-guide を参照しない（参照すると平均化バイアスが入る）
- 唯一の共有情報は **このガイド** と **タグセット**（`src/lib/tag-axis.ts`）

### 8.2 タグの公平性は中央が担保

- 並列 AI は §4.4 の公認セットのみ使う
- 「新タグを足したい」と思ったら、**勝手に足さず**、JSON の末尾コメントか PR 説明に記録 → 中央レビュアーが判断
- 中央レビュアーは月次で全番組のタグ分布を見て、偏りや欠けを補正

### 8.3 担当割り当ての推奨

- ジャンルが似た番組をまとめて 1 AI が担当しない（同じ語彙が連発するリスク）
- ランダムシャッフルで 144 番組を 10 等分（14〜15 番組 / AI）が無難

### 8.4 提出フォーマット

各 AI は以下を 1 番組ぶん 1 セットで提出：

1. `data/sources/fan-guide/{id}.json` 1 ファイル（**厳格な JSON**、コメント禁止）
2. リサーチメモ（任意）：使ったソース URL のリスト + 印象に残った素材（PR 本文に書く想定）
3. **自己レビューチェックリスト**（§9）の結果
4. **採用した型**（§4.1 のどれか）— PR 本文に 1 行：「型: もじり型 (DJ ならぬ Gyoza Jockey)」のように

### 8.5 ファイル出力時のフォーマット例

```json
{
  "id": "pcwe-XXX",
  "fanGuide": {
    "catchphrase": "...",
    "subCatch": "...",
    "genre": "...",
    "tags": ["...", "..."],
    "targetListener": "...",
    "vibe": "...",
    "themeColor": "#XXXXXX",
    "themeFont": "..."
  }
}
```

- インデントはスペース 2
- 末尾改行 1 つ
- コメント (`//` `/* */`) 禁止 — ガイドの jsonc 例示は参考用、提出物は素の JSON

### 8.6 中央レビューの観点

- ガイドのスキーマ違反はビルド時に zod が弾く（自動）
- ガイドラインの「精神」に違反していないかは人間が読む（catchphrase の凡庸さ・targetListener の属性ラベル化・他番組フレーズの流用）
- 全番組での **タグ分布の偏り**（特定タグだけ 100 番組以上 / 使われないタグ）
- **vibe / themeFont の偏り** — 7 vibe・6 font が極端に偏っていないか（§10.2 マッピング表参考）

### 10.2 vibe × themeFont マッピング（既存 10 番組クラスタ）

「番組らしさを最大限引き出す vibe + themeFont の組み合わせ」を、お手本 10 番組から逆算した参考表。

| vibe | themeFont | 番組例 | 表現する「らしさ」 |
|---|---|---|---|
| contemplative | klee-one | pcwe-006 本茶本茶 | 手書き温かみ × 静けさ |
| earnest | noto-serif-jp | pcwe-040 俺思 | 重厚な明朝 × 論考の深さ |
| energetic | rocknroll-one | pcwe-013 ピスタチオパフェクラブ | 太字インパクト × 熱量 |
| conversational | zen-kaku | pcwe-072 失敗から学ぶ | ニュートラル × 共感の余白 |
| conversational | zen-kaku | pcwe-052 シンプル KEIBA | ニュートラル × 入門者向け親しみ |
| intellectual | noto-serif-jp | pcwe-118 朝日新聞 | 重厚な明朝 × 知性 |
| intellectual | noto-serif-jp | pcwe-097 戦略的幸福論 | 重厚な明朝 × 哲学 |
| humorous | dot-gothic-16 | pcwe-119 聴く餃子 | レトロドット × 遊び心 |
| laid-back | shippori-mincho | pcwe-127 暮らしのおへそ | 上品な和明朝 × 雑誌世界観 |
| laid-back | klee-one | pcwe-100 「いま、暇？」 | 手書き温かみ × LINE 親近感 |

**選び方のコツ**:
- **klee-one**: 手書きの温かみ。"親近感" や "静けさ" を出したい時に
- **noto-serif-jp**: 重厚な明朝。"知性 / 哲学 / 報道" の硬派さに
- **rocknroll-one**: 太字インパクト。"熱量 / 深夜ラジオ / コメディ" のテンションに
- **dot-gothic-16**: レトロドット。"遊び心 / もじり / DJ 文化" の軽妙さに
- **shippori-mincho**: 上品な和。"暮らし / 雑誌 / 上質" の世界観に
- **zen-kaku**: ニュートラル現代。"親しみやすさ" に困ったらこれ（迷ったら省略してデフォルト依存も可）

## 11. AI 利用ポリシー（AGENTS.md ルール 7 改訂）

### 旧ルール（v1.3 まで）

> AGENTS.md 7. AI API の呼び出し禁止
> このプロジェクトでは Anthropic / OpenAI 等の AI API を使用しない（コスト発生のため）。
> キャッチコピー等のライティングはコエノマが手動で書き、JSON に保存する。

### 新ルール（v1.6 以降）

**禁止と OK の境界線は「API キーで自動的に叩くか / 人間が手元でエージェントに指示するか」**。

#### ❌ 禁止

- スクリプトやサイト本体から OpenAI / Anthropic 等の **LLM API を API キーで直接呼ぶ**
  （課金発生・自動運用リスク）
- 「AI に一発生成させてそのまま提出」する自動パイプラインを組む
- 公式情報そのものの生成（番組概要・ホスト名・出展情報の捏造）
- 番組制作者の主張に反する深読み・脚色
- 一度もリサーチしていない番組について「聴いた感想」を装う

#### ✅ OK

- **Claude Code / ChatGPT 等の AI エージェントが、ユーザー（コエノマ）の操作下で動き、
  fan-guide ライティングを支援する**（契約済み定額枠で動くため、API 直叩きとは別物）
- エージェントが **fetch / Chrome / `scripts/fetch-booth-info.ts` 等で情報収集** すること
- 本ガイド（§1〜§10）に従って、エージェントが下書きを書くこと
- 並列に 10 エージェント程度を立てて、各々が独立に担当番組を書くこと

#### 運用の必須条件

1. **本ガイドに従うこと**（§1〜§10）
2. **§9 の自己レビューチェックリストを必ず通すこと**
3. **人間（コエノマ）が最終確認・必要に応じ手直しをすること**
4. **About ページに「AI エージェントの支援を受けつつ、人間が最終校正」スタンスを明記すること**
5. **情報源は機械抽出（fetch / Chrome / fetch-booth-info）から取り、API での生成では補わないこと**

### About ページへの追記文（参考）

> このサイトの fan-guide（キャッチコピー・タグ・刺さりそうな人）は、コエノマと AI
> エージェントが、公式情報・配信プラットフォーム・SNS をリサーチした上で書き、
> 必ず人間が最終校正したものです。番組制作者ご本人の意図とずれている記述があれば、
